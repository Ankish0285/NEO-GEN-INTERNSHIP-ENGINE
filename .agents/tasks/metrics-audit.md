## Metric: atsScore

### Stored in
- `Resume.atsScore` — the general/composite ATS score for a resume (primary store)
- `User.atsScore` — a denormalized copy written during upload
- `AIStudentProfile.latestAtsScore` — the AI-pipeline's score, written by `persistAIProfile`

### Written by
1. `atsController.js → uploadResume` (POST `/api/resume/upload`):
   - Sets `Resume.atsScore = scoreData.score` (line ~139)
   - Sets `User.atsScore = scoreData.score` via `findByIdAndUpdate` (line ~154)
2. `aiController.js → analyzeResumeAI` (POST `/api/ai/analyze`):
   - Updates `Resume.atsScore = analysis.ats_score || resume.atsScore` (line ~269)
   - Does NOT update `User.atsScore`
3. `aiController.js → persistAIProfile` (called from `analyzeResumeAI`, `getAIIntelligence`, `runAIPipelineForUser`):
   - Sets `AIStudentProfile.latestAtsScore = pipeline.ats?.ats_score || 0`

### Read by
| Component | File | How it reads |
|---|---|---|
| `Overview.jsx` | `frontend/src/components/dashboard/student/Overview.jsx:272` | `dashboardData?.atsScore \|\| atsScoreData?.score \|\| 0` |
| `Analytics.jsx` | `frontend/src/components/dashboard/student/Analytics.jsx:37` | `atsScoreData?.score ?? dashboardData?.atsScore ?? 0` |
| `ATSResume.jsx` | `frontend/src/components/dashboard/student/ATSResume.jsx:558` | `atsScoreData?.score \|\| 0` |
| `AIIntelligenceHub.jsx` | `frontend/src/components/ai/AIIntelligenceHub.jsx:126` | `profile?.latestAtsScore \|\| ats.ats_score \|\| atsScoreData?.score \|\| 0` |
| `dashboardController.js` | `backend/controllers/dashboardController.js:25` | Reads from latest `Resume.atsScore` |
| `aiController.js` (recommendations) | `backend/controllers/aiController.js:302` | Passes `user.atsScore` to Python pipeline |

### Inconsistencies

1. **Three separate storage locations, can drift apart.**
   - `User.atsScore` is set only on upload (`atsController`). After a subsequent `analyzeResumeAI` call, `Resume.atsScore` is updated but `User.atsScore` is NOT updated, creating a stale copy on the User document.
   - `AIStudentProfile.latestAtsScore` is set by the AI pipeline and can differ from `Resume.atsScore` if the AI pipeline uses a different scoring path (Python AI vs JS fallback).

2. **Dual fallback in Overview (line 272) uses `||` not `??`:**
   ```js
   const ats = dashboardData?.atsScore || atsScoreData?.score || 0;
   ```
   If a student genuinely has `atsScore = 0`, the `||` operator skips to the next value. Both are likely 0 in that case, but a race condition where `dashboardData` is loaded before `atsScoreData` could show 0 correctly; however the behavior is misleading and fragile.

3. **Dashboard controller reads `Resume.atsScore` directly; `User.atsScore` is used only to pass context to the Python AI engine.** This means the AI engine receives potentially stale data after `analyzeResumeAI` updates only the Resume.

4. **`AIIntelligenceHub` has a 4-term fallback chain** (`profile?.latestAtsScore || ats.ats_score || atsScoreData?.score || 0`). `profile?.latestAtsScore` comes from `AIStudentProfile` (set by AI pipeline), while `atsScoreData?.score` comes from `Resume.atsScore` via `/api/resume/score`. These two can differ because the AI pipeline scores differently from the JS ATS fallback used during upload.

5. **`analyzeResumeAI` does not update `User.atsScore`** after running analysis, leaving the User document with the upload-time score even after re-analysis improves it.

### Canonical Source Recommendation
`Resume.atsScore` (from `/api/resume/score`) is the most direct single source. `User.atsScore` should be kept in sync on every write. `AIStudentProfile.latestAtsScore` should be clearly labeled as the AI-pipeline's view and not substituted silently for the general ATS score.

## Metric: employabilityScore

### Stored in
- `AIStudentProfile.employabilityScore` — set by Python profile engine's `employment_score`

### Written by
- `aiController.js → persistAIProfile` (called from all AI routes):
  ```js

  ```
  — Python field: `employment_score` / `employability_score` (see Python profile engine)

### Read by
| Component | File | How it reads |
|---|---|---|
| `AIIntelligenceHub.jsx` | `frontend/src/components/ai/AIIntelligenceHub.jsx:127` | `profile?.employabilityScore \|\| intel?.profile?.employability_score \|\| 0` |

### Inconsistencies

1. **`|| 0` truthiness check swallows genuine zero.** If a student has a legitimate `employabilityScore` of `0`, both `profile?.employabilityScore` and `intel?.profile?.employability_score` will be `0`, and the expression evaluates to `0` — which is correct in the final position. However, if `profile?.employabilityScore` exists and IS `0`, the fallback to `intel?.profile?.employability_score` will be consulted, potentially showing a different (newer or older) value.

2. **Only shown in `AIIntelligenceHub`.** `Overview.jsx`, `Analytics.jsx`, and `InternshipReadiness.jsx` do not display `employabilityScore`. No inconsistency across pages, but no shared context either.

3. **Not in `StudentDashboardContext`.** The context exposes `atsScoreData` but not `employabilityScore` or `internshipReadinessScore`. `AIIntelligenceHub` fetches these independently via `getAIProfile` and `getAIIntelligence` — separate HTTP requests from the same user session.

### Canonical Source Recommendation
`AIStudentProfile.employabilityScore` (from `/api/ai/profile` → `profile.employabilityScore`). The `||` fallback to `intel?.profile?.employability_score` is a double from the same AI run and is acceptable as a short-circuit read, but should use `?? 0` not `|| 0`.

`careerService.js` calls `api.get('/career/readiness')`, but `server.js` registers no route at `/api/career`. The registered career routes are:
- `/api/career-goals`
- `/api/career-events`

There is no `/api/career` mount. `InternshipReadiness.jsx` will always receive a network error from this fetch. The component catches the error (`console.warn`) and falls back to `readiness = {}`, rendering all sub-scores as `0`.

This means **the entire InternshipReadiness page shows 0% for every metric regardless of the student's actual profile data**, while `AIIntelligenceHub` correctly shows the value from `AIStudentProfile.internshipReadinessScore`.

Additionally:
- `AIIntelligenceHub` reads `internshipReadinessScore` from `AIStudentProfile` (set by AI pipeline)
- `InternshipReadiness` is supposed to use sub-scores (`overallScore`, `resumeScore`, `skillsScore`, `evidenceScore`, `applicationScore`, `interviewScore`) that are not even fields in `AIStudentProfile`
- There is a fundamental mismatch in what these two components are trying to show

### Canonical Source Recommendation
Create the missing `/api/career/readiness` backend endpoint. It should derive:
- `overallScore` from `AIStudentProfile.internshipReadinessScore`
- `resumeScore` from `Resume.atsScore`
- `skillsScore` from `AIStudentProfile.skillProfile` length/quality
- `evidenceScore` from `SkillEvidence` collection (already used by `careerIntelligenceController`)

### Inconsistencies

1. **Hardcoded fallback `75` in `AIIntelligenceHub` (line 248):**
   ```js

   ```
   When no analysis has been run (new user or AI offline), this displays `75%` — an invented number presented as a real metric. This violates the rule against fabricating scores.

2. **Hardcoded initialization `70` and fallback `75` in `atsController.js`:**
   - `let aiConfidenceScore = 70;` — default before AI call
   - `aiConfidenceScore = aiAts.ai_confidence_score || 75;` — fallback if AI returns falsy (0 is falsy)
   - If the Python engine returns `ai_confidence_score: 0`, the stored value becomes `75`, not `0`. This `|| 75` masks a legitimate zero.

3. **`Resume.aiConfidenceScore` stores the upload-time confidence**, while `AIStudentProfile.aiConfidenceScore` stores the pipeline-time confidence. These can diverge if `analyzeResumeAI` is called after upload (which updates only `AIStudentProfile`, not `Resume`).

### Canonical Source Recommendation
`AIStudentProfile.aiConfidenceScore` is the authoritative post-analysis value. The fallback `|| 75` in both frontend and `atsController` must be removed. If no analysis has been run, display "Not available" instead of inventing `75%`.

## Root Causes Summary

### Root Cause 1: Missing `/api/career/readiness` route
**Impact:** `InternshipReadiness.jsx` always shows 0% across all sub-metrics. The entire page is broken for every student.

**Evidence:**
- `careerService.js:12` calls `api.get('/career/readiness')`
- `server.js` registers no `/api/career` mount
- `InternshipReadiness.jsx:21–26` catches the error silently and defaults to `{}`

### Root Cause 2: Hardcoded `75` for AI Confidence Score
**Impact:** Students with no resume analysis see `75%` AI Confidence, a fabricated number.

**Evidence:**
- `AIIntelligenceHub.jsx:248`: `|| 75` as last fallback
- `atsController.js:105`: `aiAts.ai_confidence_score || 75` — also masks genuine `0` from AI engine

### Root Cause 3: Three Storage Locations for `atsScore` that can drift
**Impact:** `User.atsScore` becomes stale after `analyzeResumeAI` updates `Resume.atsScore` without syncing User. The Python engine then receives old data for subsequent recommendations.

**Evidence:**
- `atsController.js:154`: writes `User.atsScore` on upload
- `aiController.js:269`: writes `Resume.atsScore` on re-analysis, but does NOT write `User.atsScore`

### Root Cause 4: `||` truthiness checks instead of `??` for scores
**Impact:** A genuine score of `0` would trigger fallback to next value in the chain. All these locations use `||`:
- `Overview.jsx:272`: `dashboardData?.atsScore || atsScoreData?.score || 0`
- `AIIntelligenceHub.jsx:126–128`: multiple `||` fallback chains for atsScore, employability, readiness
- `ATSResume.jsx:558`: `atsScoreData?.score || 0` (only one level, less dangerous but still wrong)
- `AIIntelligenceHub.jsx:248`: `|| 75` for aiConfidenceScore (most dangerous — invents a value)

In practice, a genuine `0` score is the starting state and is rendered correctly by the `|| 0` tail. The real risk is the mid-chain `||` expressions silently switching to a stale fallback value.

### Root Cause 5: `InternshipReadiness.jsx` fetches its own data independently
**Impact:** It does not use `StudentDashboardContext`, making it isolated from the shared data layer and unable to benefit from post-upload refreshes.

**Evidence:**
- `InternshipReadiness.jsx:8`: `getReadiness` imported from `careerService`
- `InternshipReadiness.jsx:13–26`: own `useEffect` fetch, not tied to context

### Root Cause 6: `aiConfidenceScore` not in `StudentDashboardContext`
**Impact:** Only `AIIntelligenceHub` ever shows this metric. It is not synchronized with other pages.

### Root Cause 7: `User.atsScore` passed to Python AI engine but can be stale
**Evidence:** `aiController.js:124,302`: `atsScore: user?.atsScore` and `atsScore: user.atsScore` — the User document's `atsScore` may lag behind `Resume.atsScore` after a re-analysis.

## Job-Specific Match Score vs General ATS Score

| Endpoint | Route | What it scores | Where stored |
|---|---|---|---|
| Resume upload | `POST /api/resume/upload` | General resume quality against a generic job description | `Resume.atsScore`, `User.atsScore` |
| AI analyze | `POST /api/ai/analyze` | General ATS re-analysis (optionally with a job description) | `Resume.atsScore` (updates), `AIStudentProfile.latestAtsScore` |
| Single match | `POST /api/ai/match/:internshipId` | Job-specific match percentage for one internship | Not persisted — response only |
| Recommendations | `GET /api/ai/recommendations` | Per-internship `matchScore` for many internships | `Recommendation` cards in `AIStudentProfile.recommendationHistory` |

**Assessment:** Job-specific scores are correctly NOT stored back to `Resume.atsScore` or `User.atsScore`. The response from `matchSingleInternship` is ephemeral. No cross-contamination exists here.

On the frontend, `RecommendationCard` (in `Overview.jsx`) shows `job.matchScore` as "X% match" — correctly labeled as a job-specific match, not the general ATS score.

`aiChat` handler (`aiController.js:430–460`) does use `profile?.rawAnalysis` and `resume?.parsedText` to build context for the chat AI.
